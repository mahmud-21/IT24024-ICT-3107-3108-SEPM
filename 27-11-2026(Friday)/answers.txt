Answers - CampusBoot Reflection Questions

1. What would happen if @Retention(RetentionPolicy.RUNTIME) were forgotten?
Without it, the annotation gets the default retention, CLASS, which means the compiler writes it into the .class file but the JVM does not keep it available while the program runs. Calls such as isAnnotationPresent() and getAnnotation() would return false/null. The container would skip every class as "no @Component", no values would be injected, the validator would find no @Range fields and the router would never find a @Route method, so every request would give 404. The whole framework depends on reading annotations at runtime, which only RUNTIME retention allows.

2. Mapping to Spring Boot, and something real Spring does that CampusBoot does not.
@Component maps to Spring's @Component (or @Service/@Controller stereotypes), @Value maps to Spring's @Value (for example @Value("${app.name}")), @Range maps to Bean Validation constraints such as @Min/@Max (jakarta.validation), and @Route maps to @GetMapping/@RequestMapping. Real Spring also does dependency injection between beans (@Autowired / constructor injection), so one bean can receive another bean. It also supports singleton/prototype scopes, component scanning of packages, AOP proxies, and passing request parameters into controller methods. CampusBoot only creates beans with a no-arg constructor and calls methods with no parameters.

3. Why is setAccessible(true) both powerful and risky?
It is powerful because it lets reflection read and write private fields and call private methods or constructors, which is what lets the framework inject values without needing setters. It is risky because it bypasses encapsulation: code can break class invariants, change state that the author meant to protect, and depend on private implementation details that may change. It can also be a security problem if untrusted code uses it to reach sensitive data, and in newer Java versions the module system can block it (InaccessibleObjectException).
